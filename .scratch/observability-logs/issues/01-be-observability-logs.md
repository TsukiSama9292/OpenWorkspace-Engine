# 01 — Audit + Container Logs + Control-plane Rotation (backend)

**Track:** backend

**What to build:** The API half of Stage-5 observability: an audit trail that records administrative and security events into a new table and serves them to authorized viewers; an on-demand container-log endpoint that streams an instance's stdout/stderr (snapshot + live follow); and bounded log rotation for instance and control-plane containers. After this ticket, the API suite is green, `bash scripts/check.sh` is silent for both feature sets, and every endpoint, gate, and edge case below is covered by tests — the frontend just consumes the new contracts.

**Blocked by:** None — can start immediately.

**Status:** completed

- [x] Migration `000024`: new `audit_logs` table (id, created_at, actor_user_id, actor_name, action, target_type, target_id, target_name, outcome, client_ip, detail JSONB) with a `(created_at, id)` index; new `groups.can_view_audit_logs BOOLEAN NOT NULL DEFAULT FALSE` backfilled TRUE for Admin and Manager system groups by `kind` (mirrors `000022`).
- [x] RBAC plumbing: `EffectiveContext` (API) gains `can_view_audit_logs`; `AuthUser::can_view_audit_logs()` mirrors `can_view_monitoring()`; group create/update persists the flag with Admin pinned on / User pinned off.
- [x] Audit event model with the stable action vocabulary from the spec (auth.login / logout / login_failure / forbidden; instance lifecycle incl. auto_sleep / pause / unpause; template / group / user CRUD + membership_change + password_change; settings.update; registry.update — the registry is a single-URL setting, so there is no registry create/delete), target types, and the `system` actor for unattended events. For `auth.login_failure` specifically: `actor_user_id` is NULL (no authenticated user exists) and `actor_name` MUST be snapshotted from the submitted login username string, or `"anonymous"` when no username was submitted — never NULL and never empty, so the NOT NULL constraint always holds. The start route emits `instance.start` (the only lifecycle route is `/start`; `instance.restart` stays a documented-but-reserved vocabulary value).
- [x] Pure `redact_detail` (sensitive field-name redaction → `"[REDACTED]"`) and pure `client_ip` (rightmost `X-Forwarded-For`, fallback `X-Real-IP`, else None + debug) helpers, unit-tested; plus pure `redact_url_userinfo` for URL-valued fields (`registry_url`, template `docker_registry`) that a field-name keyword would miss.
- [x] Audit hooks at the route-handler boundary for every event in the spec — including `user.password_change` and authenticated-only `auth.forbidden` (anonymous 401/403 noise never audited). Read-only traffic audits nothing. The group template-whitelist and the full template field set (bandwidth / keep-time / runtime / run_config / volumes / …) are covered by the before/after diff.
- [x] Async best-effort channel: bounded tokio MPSC (1024) on `AppState`, one writer task batching 50 events / 500 ms into the repository; channel-full and DB-failure degrade to `tracing` warnings and never block the triggering handler; ordering preserved.
- [x] Graceful shutdown for the writer: the app registers a shutdown hook (this is the API's first — there was previously no signal handler in `main.rs`); on SIGTERM it closes the sender, awaits the writer's `JoinHandle` with a timeout, and flushes pending in-memory audit events to the DB before exit, so no restart loses the tail of the audit stream.
- [x] `AuditLogRepository`: `insert_batch`, `query` with keyset pagination (`ORDER BY created_at DESC, id DESC`, cursor `(created_at, id) < ($1, $2)`), `prune_older_than`. Prune runs daily from the health-worker tick behind a pure `due_for_prune` gate, retention `AUDIT_RETENTION_DAYS` (default 90).
- [x] Audit query endpoint gated by `can_view_audit_logs()` (403 otherwise): filters (action, actor substring, target substring, outcome, date range) + cursor/limit (default 50), returning entries + `next_cursor`. OpenAPI spec regenerated (18 → 20 paths); endpoint joins the fuzz surface as a safe RBAC-gated endpoint.
- [x] `DockerService::container_logs(container_id, tail, follow)` added to the mockable trait; real `DockerClient` impl via bollard logs (stdout + stderr, tail + follow) with `ContainerNotFound` distinguished; mocks return canned line sequences.
- [x] Container logs endpoint `GET /api/instances/{id}/logs?tail=200&follow=true`, authorization = `mayControlInstance` scope (owner / admin / group-instance holder on lower-tier same-group target). Status-aware SSE: running → tail + follow; stopped/paused → tail then `end` event with reason and close; starting → follow; gone container → `end (deleted)`. Client disconnect drops the Docker stream; API actively ends follow when the instance leaves `running`.
- [x] The endpoint's pre-flight checks (auth, `mayControlInstance` authorization, instance existence) MUST return standard HTTP status codes (401 / 403 / 404 with a JSON error body) BEFORE the response upgrades to `text/event-stream` 200 — so the frontend client catches non-200s on the fetch response, never inside the stream. The stream is only upgraded once every pre-flight check has passed. The container-log first-chunk peek is bounded (2 s timeout) so a quiet running container still upgrades promptly.
- [x] Instance `ContainerConfig` gains log options `json-file`, `max-size=5m`, `max-file=3` (pure builder unit-tested; an integration test asserts a created container carries them).
- [x] Compose (prod `docker/openworkspace/`): `api` service logging `json-file`, `max-size=10m`, `max-file=3`. The dev stack runs the API on the host (cargo), not in a container, so no dev-compose `logging` block applies. No Rust code change for control-plane logging.
- [x] Acceptance: `bash scripts/check.sh` silent (both feature sets), full `bash scripts/run_tests.sh` green, web `pnpm check` green (contract types not yet consumed by the UI — the new fields must not break the existing build).
